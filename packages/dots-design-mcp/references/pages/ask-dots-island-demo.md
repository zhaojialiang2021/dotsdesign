# 问点点灵动展开 demo

本 demo 验证搜索结果页里的「问点点」常规入口，以及滚动后自动出现的总结引导。视觉真相源为 Figma「7月方案」节点 `2732:96542`，方案 A 常规入口对应子节点 `2732:96885`、展开气泡对应子节点 `2732:96923`，双列笔记流对应节点 `2245:75642`，方案 B 对应节点 `2690:91595` 内的引导卡 `2690:91976`，方案 C 对应节点 `2764:122041`，后台回答状态对应节点 `2420:53070`，总结完成提示对应节点 `2724:96019` 内的 `2752:119287`。

## 目标

- 保留用户浏览搜索结果时的上下文感知，滚动两屏后再用气泡提示可总结当前结果。
- 「问点点」始终作为常规入口；气泡只承担引导，不改变入口的可用性。
- 「问点点」与气泡确认操作进入同一个回答思考页，并复用 answer-loading demo 的思考反馈能力。

## 页面结构

1. 393×852px Light-only iOS 画板。
2. 顶部状态栏、搜索框和横向搜索分类栏。
   - 搜索框固定展示「上海周末遛娃好去处」。
3. 可纵向滚动的两列搜索结果瀑布流；顶部状态栏、搜索栏和分类栏固定在画板内。
4. 分类栏右侧「问点点」入口。
5. 展开后的总结引导卡。

- 站内项目 Demo 复用回答 Loading demo 已有的方案切换交互：画布右下工具条显示第三个方案入口，点击后在工具条上方 8px 展开同一套「方案切换」面板；面板位置、尺寸、标题、关闭方式和视觉样式均由共享 `ReportDemoCanvas` 提供，不为问点点页面复制第二套实现。
- 面板仅包含「入口气泡样式」分段控制，选项为 `方案 A`、`方案 B` 与 `方案 C`。`方案 A` 对应 Figma 节点 `2732:96923` 的两行引导卡；`方案 B` 严格对应 Figma 节点 `2690:91595` 内的指向式双行引导卡 `2690:91976`；`方案 C` 严格对应 Figma 节点 `2764:122041` 的紧凑双行引导卡。三套方案只共享触发阈值、分类栏入口和进入对话能力，不共享展开态视觉结构。

## 状态与交互

### collapsed

- 「问点点」位于分类栏右侧，包含 20px 图标容器和 15px / 22px 文案。
- 初次进入不展开气泡；搜索结果累计向下滚动达到滚动视口高度的约 `0.85` 倍、即第一屏接近结束并开始进入第二屏时，自动进入 `expanded`。
- 自动展开仅触发一次；用户点击「问点点」时直接进入 `thinking`，不主动展开引导气泡。

### thinking-background

- 用户在回答完成前返回搜索结果页时，对话实例继续挂载在画板右侧，回答在后台继续生成；搜索结果的卡片顺序、随机数据和滚动位置均不重置。
- 分类栏右侧状态以 Figma 节点 `2420:53070` 为结构参考，并按最终交互移除省略号：操作区宽 95px、高 44px。首次点击「问点点」或气泡确认操作时直接进入对话，不播放图标前奏。回答未完成并从对话页返回后，入口文案显示「总结中」，20×20px 图标槽切换为组件库 [`ProcessIndicator`](../components/process-indicator.md) 的 `kind="thinking"` 播放态；Thinking 动画本体以 32×32px 居中放入固定槽并由外层裁切，不增加独立加载点，文字保留扫光动画。
- 「总结中」文字内部使用单条慢速扫光表达后台生成：高光从左向右完成一次扫过后停顿再循环，不增加独立加载点；`prefers-reduced-motion: reduce` 时关闭扫光并保持静态 `Title` 文字。
- 点击「总结中」重新进入同一个对话实例，不重启回答。真实回答进入 `done` 后，不在分类栏长期停留「已总结」：结果页改为展示下方 `completed` 完成提示；提示自动收回或用户查看完整回答并返回后，分类栏入口立即恢复为静态点点 Logo +「问点点」。回答未完成时返回不得执行该重置。
- 回答未完成期间不再触发自动总结引导气泡。

### completed

- 三套入口方案共用同一完成态，不随 `bubbleVariant` 改变。视觉严格对应 Figma 节点 `2724:96019` 内的 `2752:119287`：卡片位于 `x=16px / y=106px`，宽 361px、高 52px、圆角 16px，使用 `--always-ask-dots-island-surface` 的 90% 白色表面、6px 背景模糊和 `--shadow-ask-dots-guide` 投影。
- 卡片水平内边距为左 12px、右 16px，垂直内边距 12px，主体与操作间距 8px。主体内显示 20×20px 静态点点 Logo、`Description` 色「点点」与 `Title` 色「已帮你总结完成」；Logo 与「点点」间距 2px，主体文案间距 6px，均使用 PingFang SC Regular 15px / 22px。
- 右侧「去看看」使用 PingFang SC Medium 15px / 22px、`Title`，水平内边距 16px、垂直内边距 3px、0.5px `Separator` 描边和全圆角。点击主体或「去看看」均触发 `light` 并进入同一条已完成回答。
- 回答在结果页后台完成时立即展开完成提示；回答在对话页完成时先记录待展示状态，用户返回并完成右滑退场后再展开。完成提示出现后 3 秒内无操作则自动收回到常规「问点点」入口并释放本轮完成对话；点击进入完整回答后再返回时直接恢复「问点点」，不重复展示完成提示。
- 方案 C 的完成提示收回时复用卡片内同一组静态 Logo +「点点」节点：完成文案和「去看看」先退出，Logo +「点点」随容器从卡片左侧移动回分类栏入口，同时「问」字逐步展开，直到形成完整「问点点」；收回结束只无感切换交互层，不得先淡掉整组内容再出现另一份入口。

- 方案 A 严格对应 Figma 节点 `2732:96923`，引导卡位于 `x=16px`、`y=106px`，宽 361px、高 76px，圆角按最终确认使用 16px。

- 第一行距卡片左、上各 12px：20×20px 静态点点 Logo 槽内保留 Figma 的 14px 叶子和光学校正，Logo 与「问点点」间距 2px；「问点点」使用 PingFang SC Regular 15px / 22px，随后以 6px 间距展示 PingFang SC Medium 15px / 22px 的「笔记看花眼？试试让点点帮你总结」。
- 第二行距卡片左 12px、右 16px，操作区整体右对齐；「忽略」与「好的」均使用 PingFang SC Medium 15px / 22px，间距 20px。「忽略」使用 `Description`，点击后关闭；「好的」使用 `--always-ask-dots-action`，点击后进入总结对话，两者均无独立按钮背景。

- 「忽略」后当前页面生命周期内不再自动展开，刷新页面后重置。

### thinking

- 「问点点」和气泡确认操作共享同一个进入方法，避免两条入口产生不同的回答状态。
- 页面复用 `DottedDemoScreen` 与 answer-loading 的判断、思考指示和消息布局，不复制一套 loading 实现；外壳必须使用 `shellVariant="main-site"`，不得沿用独立端框架。
- 主站外壳以 Figma「7月方案」节点 `2245:75646` 为视觉真相源：顶部为返回、24px 用户头像 +「点点」和更多，底部为 16px 圆角的文本输入框，文案为「发消息或按住说话...」。独立端的汉堡菜单、居中 Logo、新建对话圆按钮和胶囊语音栏均不出现。
- 主站顶栏使用和页面一致的 `Bg`，不能出现独立白色底；点击顶栏返回按钮回到本 demo 的搜索结果上一级。
- 从「问点点」或气泡确认操作进入时，搜索结果页保持在下层，对话内容层从右侧 `100%` 滑入到 `0`；iOS 系统状态栏提升到画板最外层并始终固定在 `y=0`，自身保持透明且不参与横向转场。搜索结果页另设从 `y=0` 到分类栏底部的固定头部表面，使用与搜索框一致的 `--bg-base`，负责遮挡下方滚动内容；搜索栏和分类栏容器自身均保持透明。搜索栏层级必须高于分类栏，让搜索框阴影完整覆盖分类栏上缘。对话页继续由自身主站顶栏提供背景。返回时对话内容层反向滑到右侧并停驻，不卸载正在生成的回答；再次进入时从右侧滑回。进出均使用 `duration.expand` + `curve.out`。
- 用户气泡使用主站总结意图「帮我总结上海周末遛娃好去处」；进入页后不显示「我先结合小红书里的真人体验……」普通 Dots 说明气泡，也不播放判断阶段。用户问题后只展示「整理上海周末遛娃好去处」思考行。
- 只有标题的思考气泡沿用 Answer Loading 的单行 thinking 规则，由内容自然撑开；标题右侧到背景可见边界固定保留 16px，不叠加滤镜背景的额外外扩量，也不使用长思考详情态的 361px 整行固定宽度。思考标题完成后保持 2 秒，随后直接流式输出 Figma「7月方案」节点 `2245:75509` 的上海周末遛娃完整回答；不播放判断、电视、新疆、通用工具调用或额外「思考完成」折叠步骤。
- 回答状态行使用「搜索并总结47人真实经验」、头像和箭头；左侧不显示状态图标，也不保留图标占位。当前设计未提供上海来源半层，状态行不能打开默认新疆来源。
- 回答依次展示概述、5 条推荐榜单，以及上海自然博物馆、上海天文馆、世博温室花园、西岸梦中心、世界技能博物馆五个地点的说明和三图组；回答底部继续复用复制、分享、不喜欢和重新生成操作。
- 刷新或重新进入 demo 时回到搜索结果页。

## 内容与数据

- 双列笔记的内容与版式以 Figma 节点 `2245:75642` 为唯一来源：共 14 张卡片，逐条使用节点中的封面、标题、作者和头像；同名标题若对应不同作者与封面，按设计稿保留为不同卡片。
- 页面初始化时对 14 张卡片执行一次无放回随机排序，再按奇偶位分入左右两列；同一次页面生命周期内顺序保持稳定，刷新页面后重新随机。14 张卡片构成一个循环单元，循环内部不得重复卡片。
- 笔记流必须首尾连续：距离当前内容底部不足一个滚动视口时，在左右两列末尾各追加下一轮对应列的完整循环单元。追加过程不得清空或重排现有 DOM，不改变当前 `scrollTop`，因此最后一条之后直接衔接第一条且无空白、跳动或闪烁；循环复用首次生成的时间和点赞数据。
- 双列外边距和列间距均为 5px，单列宽 189px；卡片使用 4px 圆角、10px 内容内边距和 8px 标题/元信息间距。
- 初始滚动位置必须从分类栏底部开始展示第一条笔记：第一张卡片的封面顶部与 `y=150px` 对齐，不得预先藏到固定头部下方或以负偏移截断。用户主动滚动后，笔记流仍从固定头部下方经过。
- 所有封面使用固定 `189×252px` 容器并居中裁切，必须保持原始宽高比，不允许拉伸；所有头像使用固定 `24×24px` 正方形容器、圆形裁切和 `object-fit: cover`，非正方形原图不得被压扁或拉长。
- 发布时间和点赞数在页面初始化时随机生成，同一次页面生命周期内保持稳定，滚动和状态切换不得重新随机。
- 发布时间覆盖分钟、小时和天；点赞数超过 10,000 时使用一位小数的“万”格式。

## 动效

- 方案 A 容器以分类栏右侧 `x=298px / y=106px / 95×44px` 的「问点点」入口为唯一展开原点，过渡到 `x=16px / y=106px / 361×76px`；位置、宽高和圆角统一使用 `duration.morph` + `curve.morph-spring`。800ms 主体形变保留约 3% 的弹性越界后回到精确尺寸。
- 静态 Logo 与「问点点」必须是同一组共享元素，组内相对位置不变：Logo 全局位置从约 `x=310px / y=118px` 水平移动到 `x=28px / y=118px`，文字从约 `x=332px` 移动到 `x=50px`。移动过程不得隐藏、替换节点或用两份内容交叉淡化，必须清楚看到「问点点」从分类栏右侧移动到卡片左侧。
- 展开阶段增加一次性移动光效：Logo 后方附着一条约 64px 的中等强度青白柔光尾迹，随共享元素同步向左移动，峰值阶段必须在浅色卡片上清楚可辨，并在主体形变约 92% 时完全消失；卡片上边缘同时由右向左扫过一条约 80px 的细窄白色高光，并附着克制的品牌色光晕，在约 92% 时消失。两种光效都不得覆盖文字、改变卡片静态颜色或在展开完成后残留，收回阶段不播放。
