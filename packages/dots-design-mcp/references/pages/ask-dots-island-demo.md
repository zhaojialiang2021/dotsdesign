# 问点点灵动展开 demo

本 demo 验证搜索结果页里的「问点点」常规入口，以及滚动后自动出现的总结引导。视觉真相源为 Figma「7月方案」节点 `2245:74689`，入口态沿用子画板 `2245:75644`，双列笔记流对应节点 `2245:75642`，方案 A 展开气泡对应节点 `2198:68564`，方案 A 头部蒙层对应节点 `2311:20890`，方案 B 对应节点 `2603:70442`，后台回答状态对应节点 `2420:53070`。

## 目标

- 保留用户浏览搜索结果时的上下文感知，滚动两屏后再用气泡提示可总结当前结果。
- 「问点点」始终作为常规入口；气泡只承担引导，不改变入口的可用性。
- 「问点点」与「帮我总结」进入同一个回答思考页，并复用 answer-loading demo 的思考反馈能力。

## 页面结构

1. 393×852px Light-only iOS 画板。
2. 顶部状态栏、搜索框和横向搜索分类栏。
   - 搜索框固定展示「上海周末遛娃好去处」。
3. 可纵向滚动的两列搜索结果瀑布流；顶部状态栏、搜索栏和分类栏固定在画板内。
4. 分类栏右侧「问点点」入口。
5. 展开后的总结引导卡。

- 站内项目 Demo 复用回答 Loading demo 已有的方案切换交互：画布右下工具条显示第三个方案入口，点击后在工具条上方 8px 展开同一套「方案切换」面板；面板位置、尺寸、标题、关闭方式和视觉样式均由共享 `ReportDemoCanvas` 提供，不为问点点页面复制第二套实现。
- 面板仅包含「入口气泡样式」分段控制，选项为 `方案 A` 与 `方案 B`。`方案 A` 对应当前液态玻璃气泡；`方案 B` 严格对应 Figma 节点 `2603:70442` 的轻量单行引导卡，两套方案只共享触发阈值、分类栏入口和进入对话能力，不共享展开态视觉结构。
- 切换方案时重新挂载手机内的问点点演示，重置笔记流顺序与随机数据、滚动位置、引导气泡、对话和回答进度；画布自身的拖动位置、缩放比例和手机边框开关保持不变。

## 状态与交互

### collapsed

- 「问点点」位于分类栏右侧，包含 20px 图标容器和 15px / 22px 文案。
- 初次进入不展开气泡；搜索结果累计向下滚动达到滚动视口高度的约 `0.85` 倍、即第一屏接近结束并开始进入第二屏时，自动进入 `expanded`。
- 自动展开仅触发一次；用户点击「问点点」时直接进入 `thinking`，不主动展开引导气泡。

### thinking-background

- 用户在回答完成前返回搜索结果页时，对话实例继续挂载在画板右侧，回答在后台继续生成；搜索结果的卡片顺序、随机数据和滚动位置均不重置。
- 分类栏右侧状态以 Figma 节点 `2420:53070` 为结构参考，并按最终交互移除省略号：操作区宽 95px、高 44px。首次点击「问点点」或「帮我总结」时直接进入对话，不播放图标前奏。回答未完成并从对话页返回后，入口文案显示「总结中」，20×20px 图标槽切换为组件库 [`ProcessIndicator`](../components/process-indicator.md) 的 `kind="thinking"` 播放态；Thinking 动画本体以 32×32px 居中放入固定槽并由外层裁切，不增加独立加载点，文字保留扫光动画。
- 「总结中」文字内部使用单条慢速扫光表达后台生成：高光从左向右完成一次扫过后停顿再循环，不增加独立加载点；`prefers-reduced-motion: reduce` 时关闭扫光并保持静态 `Title` 文字。
- 点击「总结中」重新进入同一个对话实例，不重启回答。真实回答进入 `done` 后，20px 图标槽由 Thinking 动画恢复为静态点点 Logo，入口文案改为「已总结」；点击「已总结」重新打开同一条完整回答。用户从这条已完成回答点击返回的同一刻，下层分类栏入口立即无感恢复为点点 Logo +「问点点」，随后对话页执行右滑退场；退场结束后再释放已完成对话实例，用户重新看到结果页时不得感知「已总结」到「问点点」的切换。回答未完成时返回不得执行该重置。
- 回答未完成期间不再触发自动总结引导气泡。

### expanded

- 引导卡位于 `x=16px`、`y=66px`，宽 361px、高 106px，圆角映射 `radius.tag`。
- 展开时增加一块 `x=0 / y=0 / 393×150px` 的独立头部蒙层，覆盖搜索栏和分类栏但不拦截交互；蒙层严格使用 Figma 节点 `2311:20890` 的纵向白色渐变：顶部 100% 白，中段 `70.331%` 位置为 90% 白，底部为 50% 白。
- 层级从低到高为分类栏、搜索栏、头部蒙层、展开气泡、进入思考页后的横向转场层、固定 iOS 系统状态栏。蒙层负责压住头部操作区，气泡始终在蒙层之上；状态栏内容保持可见且不参与气泡展开。
- 容器使用 `--always-ask-dots-island-surface` 90% 白色表面与 `--shadow-ask-dots-island` 双层阴影，不使用薄荷描边、覆盖整张卡片的绿色色块或青绿色柔光切图。玻璃背景与问题/操作内容分层，背景层先使用 6px 轻微背景模糊软化下方 Tab 和图片，再通过 `backdrop-filter: url(...)` 调用 SVG `feTurbulence + feGaussianBlur + feDisplacementMap + feSpecularLighting`，重新采样并扭曲气泡后面的内容。RGB 三通道使用不同位移强度并仅合成到 8px 边缘，产生浅色背景上可见但克制的折射色散，问题和操作内容保持清晰；内容层不参与背景模糊。实现思路参考 MIT 项目 [`rdev/liquid-glass-react`](https://github.com/rdev/liquid-glass-react)，在当前页面内做无依赖的轻量实现；不支持 SVG 位移滤镜时退化为 90% 白色表面与 6px 轻微背景模糊。
- 问题行位于左上 16px，头像 20×20px，间距 6px；文案固定为「笔记太多看花眼啦？让我来帮你总结下吧~」，使用 PingFang SC Medium 15px / 22px。
- 操作区位于右下 16px，操作间距 20px；「忽略」宽 30px，使用 14px / 20px `Description`。
- 「帮我总结」高 36px、内容宽 108px、水平 padding 26px，圆角映射 `radius.full`；背景使用 `--dots-accent-surface`，文字使用 `--always-ask-dots-action`，按钮不附加模糊，避免把普通毛玻璃误认为液态折射。
- 「忽略」触发 `light` 并回到 `collapsed`。
- 「忽略」后当前页面生命周期内不再自动展开，刷新页面后重置。
- 「忽略」只关闭引导气泡，不禁用分类栏右侧的常规「问点点」入口。
- 「帮我总结」触发 `light`，先将引导气泡切回 `collapsed` 再进入 `thinking`；返回搜索结果页时保持收起，且本轮页面生命周期内不再自动展开。
- 方案 A 与方案 B 的引导气泡都使用相同自动收回规则：从展开完成开始计时，5 秒后自动收回；若 5 秒内用户继续滚动，累计滚动距离先达到 3 个结果视口高度，则立即收回。两项条件以先到者为准，收回后本次页面生命周期内不再自动展开。

### expanded / 方案 B

- 方案 B 引导卡位于 `x=16px`、`y=110px`，宽 361px、高 60px，圆角映射 `radius.input`；内部左侧 padding 为 12px，右侧 padding 为 16px，上下 padding 为 10px。
- 容器使用 `--always-ask-dots-guide-surface` 的 2% 薄荷白色表面、6px 背景模糊和 `--shadow-ask-dots-guide` 单层投影。方案 B 不使用方案 A 的头部蒙层、SVG 位移折射、液态玻璃滤镜、Lottie Logo、忽略按钮和胶囊操作按钮。
- 左侧内容宽 248px、高 40px，头像与文案间距为 10px。头像组占位 28×28px，按交互确认改为复用 `dots-logo-motion.json` 的 32×32px 点点 Lottie 画布并在固定槽内居中裁切；头像后方柔光使用 Figma 节点导出的原始资源，禁止用 CSS 渐变或自绘 SVG 替代。
- 文案在 210×40px 容器内纵向排列：上方「点点」使用 PingFang SC Medium 12px / 18px、`--always-ask-dots-action`；下方「笔记看花眼？试试点点帮你总结」使用 PingFang SC Medium 15px / 22px、`--title`，均保持单行。
- 右侧「立即总结」使用 PingFang SC Medium 15px / 22px、`--always-ask-dots-action`，不带独立按钮背景。点击后进入与方案 A 相同的总结对话；方案 B 不提供气泡内关闭操作。
- 自动出现阈值、只出现一次、回答未完成时禁止再次出现等状态规则与方案 A 一致；方案切换时仍完整重置手机内演示。

### thinking

- 「问点点」和「帮我总结」共享同一个进入方法，避免两条入口产生不同的回答状态。
- 页面复用 `DottedDemoScreen` 与 answer-loading 的判断、思考指示和消息布局，不复制一套 loading 实现；外壳必须使用 `shellVariant="main-site"`，不得沿用独立端框架。
- 主站外壳以 Figma「7月方案」节点 `2245:75646` 为视觉真相源：顶部为返回、24px 用户头像 +「点点」和更多，底部为 16px 圆角的文本输入框，文案为「发消息或按住说话...」。独立端的汉堡菜单、居中 Logo、新建对话圆按钮和胶囊语音栏均不出现。
- 主站顶栏使用和页面一致的 `Bg`，不能出现独立白色底；点击顶栏返回按钮回到本 demo 的搜索结果上一级。
- 从「问点点」或「帮我总结」进入时，搜索结果页保持在下层，对话内容层从右侧 `100%` 滑入到 `0`；iOS 系统状态栏提升到画板最外层并始终固定在 `y=0`，自身保持透明且不参与横向转场。搜索结果页另设从 `y=0` 到分类栏底部的固定头部表面，使用与搜索框一致的 `--bg-base`，负责遮挡下方滚动内容；搜索栏和分类栏容器自身均保持透明。搜索栏层级必须高于分类栏，让搜索框阴影完整覆盖分类栏上缘。对话页继续由自身主站顶栏提供背景。返回时对话内容层反向滑到右侧并停驻，不卸载正在生成的回答；再次进入时从右侧滑回。进出均使用 `duration.expand` + `curve.out`。
- 用户气泡使用主站总结意图「帮我总结上海周末遛娃好去处」；进入页后不显示「我先结合小红书里的真人体验……」普通 Dots 说明气泡，也不播放判断阶段。用户问题后只展示「整理上海周末遛娃好去处」思考行。
- 只有标题的思考气泡沿用 Answer Loading 的单行 thinking 规则，由内容自然撑开；标题右侧到背景可见边界固定保留 16px，不叠加滤镜背景的额外外扩量，也不使用长思考详情态的 361px 整行固定宽度。思考标题完成后保持 2 秒，随后直接流式输出 Figma「7月方案」节点 `2245:75509` 的上海周末遛娃完整回答；不播放判断、电视、新疆、通用工具调用或额外「思考完成」折叠步骤。
- 回答状态行使用「搜索并总结47人真实经验」、头像和箭头；左侧不显示状态图标，也不保留图标占位。当前设计未提供上海来源半层，状态行不能打开默认新疆来源。
- 回答依次展示概述、5 条推荐榜单，以及上海自然博物馆、上海天文馆、世博温室花园、西岸梦中心、世界技能博物馆五个地点的说明和三图组；回答底部继续复用复制、分享、不喜欢和重新生成操作。
- 刷新或重新进入 demo 时回到搜索结果页。

## 内容与数据

- 双列笔记的内容与版式以 Figma 节点 `2245:75642` 为唯一来源：共 14 张卡片，逐条使用节点中的封面、标题、作者和头像；同名标题若对应不同作者与封面，按设计稿保留为不同卡片。
- 页面初始化时对 14 张卡片执行一次无放回随机排序，再按奇偶位分入左右两列；同一次页面生命周期内顺序保持稳定，刷新页面后重新随机。14 张卡片构成一个循环单元，循环内部不得重复卡片。
- 笔记流必须首尾连续：距离当前内容底部不足一个滚动视口时，在左右两列末尾各追加下一轮对应列的完整循环单元。追加过程不得清空或重排现有 DOM，不改变当前 `scrollTop`，因此最后一条之后直接衔接第一条且无空白、跳动或闪烁；循环复用首次生成的时间和点赞数据。
- 双列外边距和列间距均为 5px，单列宽 189px；卡片使用 4px 圆角、10px 内容内边距和 8px 标题/元信息间距。
- 初始滚动位置必须从分类栏底部开始展示第一条笔记：第一张卡片的封面顶部与 `y=150px` 对齐，不得预先藏到固定头部下方或以负偏移截断。用户主动滚动后，笔记流仍从固定头部下方经过。
- 所有封面使用固定 `189×252px` 容器并居中裁切，必须保持原始宽高比，不允许拉伸；所有头像使用固定 `24×24px` 正方形容器、圆形裁切和 `object-fit: cover`，非正方形原图不得被压扁或拉长。
- 发布时间和点赞数在页面初始化时随机生成，同一次页面生命周期内保持稳定，滚动和状态切换不得重新随机。
- 发布时间覆盖分钟、小时和天；点赞数超过 10,000 时使用一位小数的“万”格式。

## 动效

- 容器以分类栏右侧「问点点」入口为唯一展开原点，从 `95×44px` 过渡到 `x=16px / y=66px / 361×106px`；位置、宽高和圆角统一使用 `duration.morph` + `curve.morph-spring`。该曲线离线采样为 CSS `linear()`，不是用 `cubic-bezier` 冒充弹簧；800ms 内持续完成主体形变，在约 70% 时越过目标约 3%，随后回到精确尺寸。
- 只有展开引导气泡使用 `src/assets/dotted/ask-dots-island/dots-logo-motion.json` Lottie 资源并循环播放；分类栏常规入口、已总结状态和其余 Logo 均继续使用静态 `dots-avatar.svg`。Logo 外层容器仍随气泡从分类栏右侧移动到左上角，并保持固定 20×20px 布局槽；展开态 Lottie 画布为 24×24px，在槽内水平、垂直居中裁切，不能推动文字或改变气泡布局。`prefers-reduced-motion: reduce` 时 Lottie 停在第一帧。
- 入口态与问题态必须复用同一个文字容器，并始终跟随 Logo：展开前 250ms，「问点点」从同一文字起点向左收束，随后完整问题从该起点向右展开；两段文字只通过裁切和轻微位移完成接替，不使用透明度交叉淡化，也不能放在不同位置各自入场。操作区在约 48% 后从下方轻移并显现，形成「容器 / Logo / 文字变形 → 操作」的阅读顺序。
- 收回必须播放完整反向动效，而不是直接隐藏：操作先退出，完整问题从同一文字容器向起点收束，Logo 与容器使用 800ms `curve.morph-settle` 缩回入口。前 75% 保留卡片形变的可读性，最后 25% 加快尺寸、位置和圆角归位，并在约 85% 时越过收起目标约 3% 后回稳；卡片表面和阴影在主体收缩前 75% 保持 100%，最后 25% 开始渐隐，且最后 10% 进一步提速到 0 并融入分类栏，避免只剩淡出、末帧挤成色块或到达入口后硬切。最后 250ms 再由同一文字起点展开「问点点」，形成「问题文案 → 问点点」的明确逆过程。
- 两套方案的容器内容与卡片使用同一 800ms 时间轴：展开时 Logo、文案和操作从 `84%` 尺寸逐渐放大，在约 70% 时到 `103%` 后回到 `100%`，模糊从 4px 降到 0；收回时先从 `100%` 缩小，在约 85% 时比收起内容目标多缩 3%，随后回到正常目标，同时从清晰逐渐变模糊，并让展开内容的透明度在完整收回时长内从 `100%` 线性降到 `0%`。透明度只辅助共享元素收束，不能替代内容缩放，也不能让内容先于容器结束运动。
- 回答尚未完成时点击对话页返回，先按既有规则完成右滑退场；结果页重新完整出现后，分类栏固定图标槽播放 `ProcessIndicator kind="thinking"`，文案显示「总结中」。首次进入对话时下层结果页不会提前展示该动画；文字保留扫光动画。
- 按压反馈使用全局 `press-scale` 与 `press-opacity` 令牌。
- `prefers-reduced-motion: reduce` 时页面滑动与气泡位移都缩短为近即时切换，不保留可感知位移。
- 方案 B 仍从分类栏右侧常规入口展开，但只对容器位置、宽高、圆角和内容显隐使用共享动效令牌；不继承方案 A 的液态折射、卡片双层动作编排和 Lottie 动画。收起时 48px 卡片表面持续附着到入口尺寸后再恢复常规入口，不能先隐藏卡片。
